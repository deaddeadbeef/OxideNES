### Task 2: Enhanced CRT Glass Effect

**Problem:** Current glass effect (build_glare_table, main.rs:2729-2769) is subtle — just a faint diagonal band and a small specular dot, capped at intensity 30. Needs more convincing glass curvature, reflections, and depth.

**Design:**

Step 1: Enhance the glare table with multi-layer glass simulation

Replace current `build_glare_table()` with richer glass effects:

```
Layer 1: Fresnel edge brightening — glass edges catch more light
         Intensity increases near screen borders (opposite of vignette)
         Formula: edge_glow = (1.0 - (1.0 - border_dist)^3) * 20

Layer 2: Specular highlights — two highlight spots (upper-left, lower-right)
         Simulates overhead room lighting reflecting off curved glass
         Gaussian spots with σ=60, peak intensity 45

Layer 3: Diagonal reflection band — wider and softer than current

Layer 4: Subtle screen-edge darkening at glass borders
```

Step 2: Add dynamic glare opacity tied to content brightness

Instead of static additive glare, modulate glare visibility based on how dark the game scene is. Dark scenes → glare more visible (realistic). Bright scenes → glare fades.

Step 3: Add subtle glass curvature color fringing

### Task 4: Shadow Mask / Aperture Grille

**Problem:** No sub-pixel pattern simulation. Real CRTs have visible RGB phosphor patterns (shadow mask = dot triad, aperture grille = vertical stripes).

**Files:**

**Design:**

Step 1: Add mask mode to CrtConfig

```rust
    Off,
    ShadowMask,
    ApertureGrille,
}
```

Add `mask_mode: CrtMaskMode` to CrtConfig (default: Off).

Step 2: Build shadow mask lookup table

Pre-compute a `mask_table: Vec<(u8, u8, u8)>` of size SCREEN_W × SCREEN_H at startup. Each entry is an RGB multiplier (0-255).

Shadow mask (3×3 repeating dot triad):
```
Row 0: R(255,80,80)  G(80,255,80)  B(80,80,255) — repeat
Row 1: shift right by 1
Row 2: shift right by 2
```

Aperture grille (3-column repeating vertical stripes):
```
Col 0: (255, 100, 100) — red emphasis
Col 1: (100, 255, 100) — green emphasis
Col 2: (100, 100, 255) — blue emphasis
```

Step 3: Apply mask in crt_filter()

After computing the final pixel color, multiply each channel by the mask value:
```rust
if mask_mode != CrtMaskMode::Off {

    r = (r as u16 * mr as u16 / 255) as u32;
    g = (g as u16 * mg as u16 / 255) as u32;
    b = (b as u16 * mb as u16 / 255) as u32;
}
```

**Design:**

Each mapper follows the same pattern — implement the `Mapper` trait. Add one at a time with the game that tests it.

#### Step 1: Mapper 34 (BNROM/NINA-001) — simplest first

BNROM: 32KB PRG bank switching, no CHR banking. Similar to AxROM.

```rust
pub struct Mapper034 {
    prg_rom: Vec<u8>,
    chr_rom: Vec<u8>,
    prg_ram: Vec<u8>,
    mirroring: Mirroring,
    prg_banks: usize,
    bank_select: u8,
}

impl Mapper for Mapper034 {
    fn read_prg(&self, addr: u16) -> u8 {
        match addr {
            0x6000..=0x7FFF => self.prg_ram[(addr - 0x6000) as usize],
            0x8000..=0xFFFF => {
                let offset = self.bank_select as usize * 0x8000;
                self.prg_rom[offset + (addr - 0x8000) as usize]
            }
            _ => 0,
        }
    }
    fn write_prg(&mut self, addr: u16, data: u8) {
        match addr {
            0x6000..=0x7FFF => self.prg_ram[(addr - 0x6000) as usize] = data,
            0x8000..=0xFFFF => {
                if self.prg_banks > 0 {
                    self.bank_select = (data as usize % self.prg_banks) as u8;
                }
            }
            _ => {}
        }
    }
    // read_chr/write_chr/mirroring same as Mapper000 pattern
}
```

Test ROM: Deadly Towers, Impossible Mission II.

### Task 8: APU Accuracy Improvements

**Problem:** Several APU timing edge cases not emulated. Affects games that rely on precise audio timing.

**Files:**
- Modify: `src/apu.rs` — tick/clock functions, channel implementations
- Modify: `src/bus.rs` — DMC DMA handling
- Modify: `src/cpu.rs` — cycle stealing support

**Design:**

#### Step 1: DMC DMA cycle stealing

When the DMC channel needs a sample byte, the CPU is halted for 1-4 cycles while the DMA reads from memory. Currently the emulator skips this.

In bus.rs, when the DMC triggers a fetch:
```rust
// In Bus::tick() or wherever APU is clocked:
if self.apu.dmc_needs_fetch() {
    let addr = self.apu.dmc_address();
    let data = self.cpu_read(addr);  // Read from PRG
    self.apu.dmc_load_sample(data);
    self.dmc_stall_cycles = match self.cpu_cycle_parity {
        0 => 4,  // Even CPU cycle: +4
        _ => 3,  // Odd CPU cycle: +3
    };
}
```

Add `dmc_stall_cycles` to Bus, decrement in CPU tick, skip CPU execution while > 0.

#### Step 2: Length counter halt behavior

The length counter halt flag ($4000/$4004 bit 5 for pulse, $4008 bit 7 for triangle) should prevent the length counter from being decremented by the frame counter, but it should NOT prevent the channel from being silenced when the length counter reaches zero from a previous state.

Audit the current implementation in apu.rs and verify the halt flag is checked correctly in the frame counter's half-frame clock.

#### Step 3: Noise channel period table verification

Verify the 16-entry noise period lookup table matches the hardware:
```rust
const NOISE_PERIOD_TABLE: [u16; 16] = [
    4, 8, 16, 32, 64, 96, 128, 160,
    202, 254, 380, 508, 762, 1016, 2034, 4068
];
```

Also verify short mode uses bit 6 (not bit 1) for feedback.

#### Step 4: Frame counter IRQ

Frame counter mode 0 should generate an IRQ at step 3 (every ~29830 CPU cycles). Currently may not be generating the IRQ or the CPU may not be picking it up.

In apu.rs frame_counter_clock():
```rust
if self.frame_counter_mode == 0 && self.frame_step == 3 {
    if !self.frame_irq_inhibit {
        self.frame_irq_pending = true;
    }
}
```

Wire `frame_irq_pending` into Bus's IRQ line alongside mapper IRQ.

**Verify:** Run blargg's APU test ROMs (apu_test suite) — reports pass/fail on screen.

**Commit:** `fix: APU accuracy — DMC DMA, length counter halt, frame IRQ`

### Task 9: PPU Edge Cases

**Problem:** Some games rely on precise PPU timing behaviors not yet emulated.

**Files:**
- Modify: `src/ppu.rs` — cpu_read/cpu_write, tick(), rendering logic

**Design:**

#### Step 1: Mid-scanline sprite 0 hit timing

Sprite 0 hit should only be detected when both BG and sprite pixels are non-transparent AND rendering is enabled AND we're not at x=255. The current implementation checks at pixel output time which is approximately correct, but the exact cycle should match hardware.

Verify the hit is NOT set:
- At x=255 (rightmost pixel)
- When BG or sprites are disabled via $2001
- During vblank

#### Step 2: $2006/$2005 mid-frame scroll splits

Writing to $2006 during rendering causes immediate updates to the v register. Many games use this for split-screen effects (status bars). The current implementation updates v on the second $2006 write, which is correct. Verify that the t → v transfer at cycle 257 and cycles 280-304 of pre-render scanline work correctly with mid-frame $2006 writes.

#### Step 3: Open bus behavior for $2002 reads

Reading $2002 should return the top 3 bits (VBL, S0H, SOV) in bits 7-5, with bits 4-0 coming from the PPU's internal data bus (last value written to any PPU register). Currently returns `(status & 0xE0) | (ppu_data_buffer & 0x1F)`.

Fix: use `open_bus` instead of `ppu_data_buffer` for the low 5 bits:
```rust
0x2002 => {
    let data = (self.status & 0xE0) | (self.open_bus & 0x1F);
    // ... rest unchanged
}
```

#### Step 4: Palette read-back from $2007

Reading palette RAM ($3F00-$3FFF) via $2007 should return the palette value immediately (not buffered), while also loading the buffer with the nametable data "underneath" the palette address. This is already implemented correctly — verify and add a test assertion.

**Verify:** Run blargg's PPU test ROMs. Test games: Battletoads (sprite 0 for status bar), SMB3 (scroll splits), Mega Man 3 (various PPU tricks).

**Commit:** `fix: PPU accuracy — sprite 0 timing, open bus, scroll splits`

#### Step 2: Create netplay module

```rust
// src/netplay.rs
pub struct NetplaySession {
    socket: UdpSocket,
    peer_addr: SocketAddr,
    local_player: u8,        // 0 = P1, 1 = P2
    input_delay: u8,         // Frames of input delay (1-5)
```

#### Step 3: Input exchange protocol

Each frame, both players send a packet:
```
[0x4E 0x50]     Magic "NP"
[u64]           Frame number
[u8]            Input bits (same as NES joypad byte)
[u32]           State checksum (PPU frame hash for desync detection)
```

Total: 15 bytes per frame per direction.

Non-blocking receive: poll for remote input. If not received within input_delay frames, predict (repeat last input). If received late, rollback isn't implemented in v1 — just skip.

#### Step 4: Integrate into game loop

In handle_input(), when netplay is active:
- Read local input as normal → queue it
- Send local input packet to peer
- Receive remote input packet
- Apply: local player's input to their joypad, remote player's to the other
- Delay local input by `input_delay` frames for fairness

#### Step 5: Host/Join UI in menu

- JOIN: Enter IP:port → connect

Create a JSON database of known ROMs:
```json
{
  "crc32_index": {
    "A5B8B3E0": {
      "title": "Super Mario Bros.",
      "region": "USA",
      "mapper": 0,
      "mirroring": "vertical",
      "prg_size": 32768,
      "chr_size": 8192,
      "battery": false
    }
  }
}
```

Source: public NES cart databases (NesCartDB, No-Intro). Include top ~2000 games. Embed in the binary using `include_str!` or load from `~/.nes-emulator/romdb.json`.

#### Step 2: ROM identification

On ROM load, compute CRC32 of the PRG+CHR data (excluding the 16-byte header):
```rust
fn compute_rom_crc32(rom_data: &[u8]) -> u32 {
    let has_trainer = rom_data[6] & 0x04 != 0;
    let data_start = 16 + if has_trainer { 512 } else { 0 };
    crc32fast::crc32(&rom_data[data_start..])
}
```

Add `crc32fast = "1"` to Cargo.toml.

#### Step 3: Auto-fix bad headers

If the ROM is identified in the database, compare its header against the known-good values. If the mapper number, mirroring, or sizes don't match, **use the database values** instead:

```rust
if let Some(db_entry) = romdb.lookup(crc) {
    if db_entry.mapper != header_mapper {
        eprintln!("Header fix: mapper {} → {} ({})", header_mapper, db_entry.mapper, db_entry.title);
        mapper_id = db_entry.mapper;
    }
    // Same for mirroring, battery flag
}
```

This supersedes the DiskDude! heuristic — database is authoritative.

#### Step 4: Display game info

Show identified game title in:
- Window title bar: "NES Emulator — Super Mario Bros."
- File browser: display database title next to filename
- Pause menu: show title, mapper, region

For unidentified ROMs, fall back to filename.

#### Step 1: Version check on startup

On launch (in a background thread to not block startup):
```rust
fn check_for_updates() -> Option<UpdateInfo> {
    let resp = ureq::get("https://api.github.com/repos/USER/nes-emulator/releases/latest")
        .call().ok()?;
    let json: serde_json::Value = resp.into_json().ok()?;
    let latest_tag = json["tag_name"].as_str()?;
    let latest_ver = semver::Version::parse(latest_tag.trim_start_matches('v')).ok()?;
    let current_ver = semver::Version::parse(env!("CARGO_PKG_VERSION")).ok()?;
    if latest_ver > current_ver {
        Some(UpdateInfo {
            version: latest_tag.to_string(),
            download_url: json["assets"][0]["browser_download_url"].as_str()?.to_string(),
            changelog: json["body"].as_str().unwrap_or("").to_string(),
        })
    } else {
        None
    }
}
```

```toml
semver = "1"
# ureq already added in Task 12
```
